# ربط ملفات المشتري تلقائيًا — تصميم المرحلة التالية

هذا التصميم لم يُنشر كخدمة. لا يوجد حاليًا مزود شهادات أو API مربوط، ولا يرسل التطبيق مفاتيح المشتري لأي جهة.

## ثلاثة أشياء منفصلة

- كود IDK1: يثبت اشتراك المستخدم ويرتبط بمعرّف تثبيت idk plus. هذا المعرّف ليس UDID.
- ملف .mobileconfig: قد يطلب بيانات الجهاز بموافقة المستخدم، أو يضيف رابط متجر للشاشة الرئيسية (Web Clip)، أو يسجّل جهازًا في إدارة أجهزة. وجوده وحده لا ينشئ شهادة توقيع تطبيقات Apple.
- شهادة P12 وملف .mobileprovision: ملفات توقيع تحتاج جهة تملك صلاحية إصدارها. في توزيع Ad Hoc يلزم تسجيل الجهاز وإضافته إلى ملف التوقيع.

## المسار المقترح

1. صفحة HTTPS يقبل فيها المشتري التسجيل ويثبت ملف Profile Service ليرسل الجهاز UDID والتحدي إلى الخدمة.
2. الخدمة تتحقق من الرد والتحدي وتربط UDID بالمشتري وكود الاشتراك. رابط الاستدعاء لا يعتمد على UDID يكتبه المستخدم دون تحقق.
3. المالك يجهّز الملف عبر Apple Developer أو يربط API مزود شهادات مصرح به، ويُظهر حالة الطلب (بانتظار/جاهز/فشل).
4. تطبيق idk plus بعد تفعيل الكود يثبت امتلاكه جلسة المشتري، ويحصل على حزمة ملفاته من رابط HTTPS قصير العمر، خاص به وقابل للاستخدام مرة واحدة.
5. التطبيق يستورد الملفين ويجري نفس الفحص المحلي قبل فتح المتجر. تبقى موافقات iOS على ملف التعريف والتثبيت بيد المستخدم.

## ما يلزم قبل التنفيذ

- اسم مزود الشهادات وتوثيق API أو آلية تجهيز ملفات Apple Developer.
- خدمة HTTPS مع تخزين خاص للمشتركين والملفات ومفاتيح الخدمة. يمكن فصل واجهة المتجر الثابتة عن خدمة المشتركين؛ GitHub Pages وحده لا ينفذ جلسات API أو يستقبل POST تسجيل الجهاز.
- تحديد هل التوقيع يبقى داخل الآيفون أم يجري في خدمة التوقيع. إرسال P12 إلى المشتري يمنحه نسخة من مفتاحها الخاص؛ لا ترسل مفتاح توزيع مشتركًا عامًا ضمن التطبيق أو ملف JSON أو مستودع عام.
- فترة صلاحية لكل حزمة وسجل تنزيل وإمكانية إلغاء رمز التسليم، وعدم تسجيل كلمة مرور P12 في السجلات.

ملف تعريف يضيف هوية PKCS12 إلى نظام iOS لا يعني تلقائيًا أن تطبيق المتجر يستطيع استخراج مفتاحها الخاص. لذلك التصميم المقترح يستورد حزمة ملفات مصرحًا بها داخل التطبيق أو يستخدم توقيعًا من جهة الخدمة، ولا يعتمد على استخراج أسرار النظام.
